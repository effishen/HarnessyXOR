# Changes

## 0.2.0-alpha.1 — project-first foundation

Create a project with its own principal architect, permanent knowledge and agent team. This replaces the earlier projects-as-chats direction with a fresh architecture; HarnessyXO project/database compatibility is no longer a target.

- Delegate work to project-owned agents with separate conversations, tasks and Git working copies. Waiting releases inference slots; pause, resume, stop and follow-up work are explicit.
- Preserve architectural decisions, requirements, rejected approaches, test catalogs and agent provenance across revisions and replacements.
- Inspect local commits, branches, diffs, proposed integrations, discussions, independent reviews and regression evidence.
- Fence acceptance to the exact integrated commit/tree, canonical base and current intent/catalog/policy revisions. Agent claims cannot establish passing test receipts.
- Keep initial source setup as an explicitly unverified baseline. After team work starts, canonical source changes must pass the proposal gate.
- Execute fixed native regression checks. Command and physical/manual checks remain pending until supported isolated execution or operator evidence is available.

This is an early foundation. Native host, real model and actual VM/hardware success paths remain unverified. No GitHub release or hosting publication is claimed by this source archive.

## 0.1.0-alpha.1 — initial port

Start the Rust application without a Python runtime. Connect an existing OpenAI-compatible or Ollama model server, create a workspace, and keep project conversations, files and memory together.

- Stream replies, reasoning and tool results; control global agent slots, cancel work, grant tool approvals and retry with `CONTINUE`.
- Edit and upload project files, download them, create ZIPs, extract supported ZIPs into new folders, and recover files from trash.
- Keep project locks, archives, parent links, bookmarks and saved-conversation search. Export JSON or Markdown.
- Register existing Lima VMs. Linux command execution checks exact project grants, a fresh mount proof and guest filesystem isolation.
- Create a separate host-local login account. Saved model keys remain redacted; diagnostics exclude conversations, files, memory, credentials and raw tool payloads.
- Import a copy of supported HarnessyXO v0.7.36 workspace data while preserving the source and an inactive legacy snapshot.

This alpha is a partial port. Automatic VM setup, VNC, snapshots, radios, complete Windows/OpenWrt execution, subagents, browser/web/process tools, historical rewinds, PDF exports, notifications and automatic updates still need work. See [the port status](docs/PORTING.md). Linux automated checks use synthetic model services; native platform, real model and VM success paths remain unverified.

No replacement release for HarnessyXO is claimed.
